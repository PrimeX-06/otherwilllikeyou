# 第三幕 · 校园日常

《我们的故事》第三幕。不是一条主线，是四个散在不同日子的课间小事：
送一趟东西、找一张卡、猜几个词、打一场球。

文件夹叫 `act5`，是因为它在工程里排在第四幕之后；故事里它是**第三幕**。
这个错位是历史原因，不改目录名了——改了两边的存档键和资源路径都得跟着动。

打开方式：直接用浏览器打开 `daily.html`（`file://` 就行，没有构建步骤、没有模块、
不加载音频文件，所有声音都是 Web Audio 现场合成的）。

| `tools/playall.cjs` | 「按顺序开始」整链路通关 |

`trio.js` 和 `explore.js` 是两套走位，不是重复：

- **trio** 管的是「有人跟着你」——跟随增益、互相让位、带路的人被落下会回头等。
- **explore** 管的是「只有你一个人」——一条 x 轴、一张场景表、走到边缘换图。

G01 里三个人一起走，用 trio；G02 里她俩在教室门口等，只有玩家一个人在楼上楼下翻，用 explore。
`errand.js` 没有改用 explore，因为它的换场景和交接演出焊在同一个状态机里，
搬过去得把 `state` 一起搬，风险大于收益。G04 干脆不用走位层——三个人站成一个松散的三角，
只有球在动，人只在「换个位置」和「去捡球」时挪一下，所以没再迁 trio。

## 三、为什么是横版一维

项目里所有学校场景素材都是正面平视的横版走廊（墙地分界在 y≈200）。
做俯视格子地图会和现有美术直接打架——走廊图根本没有「地面纵深」可以走。

所以「走路」只沿 x 轴，深度靠两件事假装出来：

1. 三个人站在**不同的 y** 上（`boy 226 / girl 214 / friend 238`），画的时候按 y 排序，
   互相穿过时看起来是前后错开，不是叠在一起。
2. `depthScale(y, 204, 244)` 给一点缩放（0.92–1.06）。

走位线定在 225 附近是算过的：再往下就站到画面最前沿，对白框一出来整个人就没了。

## 四、四个小游戏

### G01《一起去办事》

三个场景连成一条路：走廊（她们教室门口）→ 楼梯口 → 楼上护栏走廊（收集箱在尽头）。

- 玩家只管男主，闺蜜知道地方，出发时会自己走到前面**停下等**——
  不是从人堆里穿回来，而是先跑到目标点站住，玩家走过去之后她自然落到队尾。
- 沿途两个互动点是可选的，不影响通关。
- 被落下 1.8 秒，闺蜜会回头说一句「你怎么还在后面？」。只说一次，而且不写成责怪。

### G02《校园寻物》

周三中午，她的校园卡不见了。她在门口翻书包，你一个人出去找。

- **八处可看的东西，只有四处跟卡有关。** 其余的不是假线索，是真的、但没用的观察——
  找东西的时候本来就大部分白看。
- 线索分三种，**亲眼看见 / 我记得 / 我猜的**，在线索本里分栏列，样式也不同：

  | 类 | 说话方式 | 样式 |
  |---|---|---|
  | `see` | 「笔帽没盖」 | 实线 + 暖色 |
  | `remember` | 「她说过……」 | 实线 + 冷色 |
  | `guess` | 「……有人刚扶过。」「（这是猜的。也可能只是谁的手蹭到了。）」 | **虚线** + 灰紫 |

  猜的那条必须**在对话里就说破**，不能只在笔记本上贴个标签、嘴上说得跟亲眼看见一样。
  `check.cjs` 会断言这句话还在。

- 卡一直躺在楼梯口的窗台上，**不需要听完任何线索就能捡**。提前找到的话，
  收尾对话是「你怎么直接就找到了」，不会拦你。
- 三级提示走「问问闺蜜」：她人不在场，发消息过来。一次比一次具体，
  第三次之后按钮变「问过了」：

  1. 你先别翻了。她上午就出去过一次，就一会儿。
  2. 出去那次是接水。接水得刷卡。
  3. 楼梯口那个窗台。你去看一眼就知道了。

- 收尾按「看了多少」分三种说法。三种都只说她怎么反应，不说她高不高兴。

### G03《课间猜词》

三回合：闺蜜主持 → 朱里主持 → 闺蜜主持。默认点选项，也可以直接打汉字。

- 打汉字的时候**地图按键必须让路**，否则打字就把人走出去了（`core.js` 的 `typing()`）。
- 同义词算对，「粉笔」和「铅笔」不算对（`norm()` 只去标点，不做模糊匹配）。
- 没有倒计时。答错就多给一条线索，线索用完直接公布答案，照样往下走。
- 成绩只改收尾那句话的措辞，**没有任何数值**。

### G04《体育活动》

下周一放学后，楼前那块空地。**球用足球**，但这里不是比赛：
只踢地面滚球，不射门、不计分、不判输赢，连「好球」这种词都不出现。

「女生不大会踢球」不是一句台词了事，是三条机制：

1. **会踢歪。** `wobbleFor()` 让朱里隔一脚偏一点、闺蜜偏一脚，球路真的会歪。
   歪了她们自己说「啊，歪了」「我好像有两脚踢歪了」，接球的人会**主动挪过去够**，
   不是把球瞬移吸到脚下。
2. **传给她要更轻。** 朱里的舒服区比别人窄（`girlSweet`），力度过了球就停不住，
   滚开让人去捡。开场的「我不太会踢」和这条是对上的。
3. **慢一点。** 她拿球后停顿更久，不把节奏带成来回抽射。

玩法：

- `A / D`（或左右键）选传给谁；按住空格蓄力，**绿区里松开**。触屏有选人按钮和圆形蓄力键。
- 球滚到脚边按空格接。窗口三档：`±120ms` 稳稳接住 / `±260ms` 接得有点狼狈 /
  `±400ms` 勉强碰到；太早按不罚，还能再按。
- **目标是 5 次「玩家参与」的有效传接。** 两个 NPC 自己互传不算数——
  最早的版本把 NPC→NPC 也计进去，她俩自己传满 5 次就收尾了，玩家一脚没碰。
- NPC 会自己选目标，而且**必须有互传**；同时挡住「连续三回合不传给玩家」和
  「球一直在两个 NPC 之间循环」两种情况。
- 漏接了球就滚开，离得近的人去捡，捡回来接着踢。**没有失败画面。**
- 球在飞的时候只许有一句话的短气泡（「这边」「我去捡」），**不弹完整对白框**，
  否则一传球画面下半截就被字盖住。
- 用带种子的伪随机数，整局可复现，自检不会今天过明天挂。

收尾是「球停在中间，谁也没去捡」「三个人在台阶上坐了一会儿。上课铃还没响，
也没人提刚才传了几个」。HUD 留着 `传接 5 / 5` 直到对白读完——它是给玩家看的一句记录，
不是分数。退回目录时由章节壳统一 `dispose()` 收掉。

背景复用 `assets/scenes/school_exterior.png`（512×288，地面从 y≈190 起是平的），
只补两道粉笔线把「可以踢球的一小块地方」圈出来。**没有另做俯视操场**——
理由见第三节，俯视和这套横版美术会打架。

## 五、五条原则落在哪儿

| 原则 | 落实方式 |
|---|---|
| 人物首先是生活中的人 | 卡丢了要先跑食堂、闺蜜说「我坐她旁边，天天听她提」——先有生活，才有别的 |
| 不是每个小游戏都要制造心动 | G02 全程她俩在门口等，收尾只到「谢谢」；G01 结尾是「下节数学」；G04 结尾是「上课铃还没响」 |
| 闺蜜不能每次出现都起哄 | 她在 G01 带路、在 G03 主持、在 G04 只是踢球和捡球、在 G02 人根本不在场（只发消息）。`check.cjs` 断言她在一场里的台词不超过一半 |
| 不按小游戏成绩决定感情走向 | 四个游戏都没有分数影响；G03 的成绩只改一句台词的措辞，G04 的传接次数只写进存档、不写进对白 |
| 尊重真实记忆 | 物品、规则、台词、地点都是可替换的示例，换掉不影响结构 |

存档只记「做过什么」：`errandCompleted`、`searchCompleted`、`searchClues`、`searchHints`、
`wordGameCompleted`、`wordGameCorrect`、`wordGameHints`、`ballGameCompleted`、
`ballGamePasses`、`ballGameMisses`、`ballGameNpcToNpc`、`chapterDailyDone`。
**没有任何一个数字代表「她有多喜欢你」**。
`check.cjs` 会扫掉注释后检查正文里不出现「好感度 / 心动值 / 认可度 / 喜欢你」。

## 七、自检

```
node act5/tools/check.cjs       # 静态 + 四个游戏各走一遍
node act5/tools/playall.cjs     # 「按顺序开始」整链路
```

- **静态**：三张精灵表尺寸与帧数、`.face` 的 `background-size`、脚本无 ES module 语法、
  题库自洽、G01/G02 场景连线对称、G02 线索分类齐全且「猜的」在对话里说破、
  可看点 6–8 处、闺蜜台词占比、文案红线；
  G04 的三档接球窗口 / 5 次目标 / NPC 互传 / 「不大会踢球」/ 无竞技用词、
  章节壳有没有调 `dispose()`。
- **浏览器**：目录四项（4 可玩 / 0 锁着）→ G02 走两遍（一遍一句不问直接找到，
  一遍看全了再找）→ G01 → G03 → G04。断言状态机、线索分类、提示三级递进、
  存档、「对白打开时人物不能动」；G04 还测漏接自然恢复、选人、蓄力、
  重传停不住、NPC 互传、踢歪、球不出界、飞行时不弹对白框、退回目录后 HUD 收掉。
- **整链路**：`playall.cjs` 按周一→周三→周五→下周一自动打完四个游戏，

## 八、踩过的坑

1. **换场景那句旁白不是立刻弹的。** 它要等淡入结束（约 0.5 秒）才出来。
   自检里如果在场景刚换就往下走，人物被冻在原地，`walk` 第一圈就退出，位置一步没动。
   现在用 `approach()`：先确保对白读完再走，被打断就补一次。

2. **`extras` 是每个场景都画的。** 朱里和闺蜜站在走廊门口，玩家上楼时她俩也跟着出现在楼梯口。
   必须在 `update()` 里按场景关掉（`hidden`），不能只靠初始位置。

3. **线索本面板太矮会露馅。** 下沿正好卡在她们脚踝上面，背景里露出两双鞋，像画错了。
   面板加了 `min-height`，按钮用 `margin-top: auto` 钉在底部，中间空出来的就当本子还没写满。

4. **换精灵表忘了改 `.face` 的宽度**（见第六节）。这是真踩过的：v2 换图之后三个头像全成了小人。

5. **互动点只建一次。** 每帧新建对象的话 `used` 标记会跟着丢，同一个点能反复触发。

6. **Tab 要拦。** 不 `preventDefault` 的话焦点会跑走，接着按空格就在点按钮了。
   已加进 `core.js` 的 `BLOCK`。

7. **`#fade` 盖在所有面板上面。** 猜词面板一开就是全黑——因为上一段结束时 fade 停在 1。
   面板启动时先 `await D.fadeTo(0, 320)`。

8. **打汉字时人物乱走。** `keydown` 里先判断 `document.activeElement` 是不是输入框，
   是就直接 return，连 `preventDefault` 都不做（不然输入法候选框会出问题）。

9. **NPC 自己把 5 次传满了。** 最早 `catchBy()` 把 NPC→NPC 也算一次有效传接，
   她俩互相传几脚游戏就收尾，玩家一脚没碰。改成只计 `who === "boy" || from === "boy"`，
   再给 `chooseTarget()` 加一条「连续三回合没传给玩家就传玩家」。

10. **测试脚本等不到玩家拿球。** 循环里干等 `holder === "boy"`，可球传过来时脚本不按空格，
    全漏光了，22 秒超时。改成「边接边等」：球到脚边按空格、拿到球就轻传。

11. **收尾 HUD 停在 4/5。** `update()` 一够 5 次就 `return`，最后一帧 `syncHud()` 没跑。
    在 `finish()` 里补写 `5 / 5`，让它在收尾对白期间留着，**对白读完再由 dispose 收掉**。

12. **章节壳从来没调用过 `dispose()`。** `runGame()` 只 `resolve()`，于是 G04 的
    「传接 5/5」一直挂在目录页和结果卡上方。现在在 `currentResolve` 里统一调
    `game.dispose()`；`check.cjs` 静态和浏览器各有一条断言看着。

13. **收尾截图拍得太早。** 目标卡是 0.25s CSS 淡出、目录是 rAF + 淡入，截图卡在半透明帧，
    看起来像「目标卡没撤」「目录空白」。拍之前等 340 / 380ms，别去改逻辑。

14. **球赛的两处遮挡。** 力度条说明字原来在条上方，正好压住球和男主的腿——
    挪到条下方、缩到 8px、加半透明底；气泡原来挂得老高，像贴在墙上的牌子——
    y 从 `-30` 改到 `-20`，收尾时再 `bubbles = []` 清掉「这边」，
    免得跟「谁也没去捡」打架。
